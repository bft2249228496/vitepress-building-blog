package.json 文件中 scripts 属性的配置 ​

ESLint 与 Prettier 格式化指令配置 ​

在 package.json 的 scripts 中配置代码检查与格式化：

json
{
  "scripts": {
    // 检查并自动修复 src 目录下所有 .js 和 .vue 文件
    "lint": "eslint --ext .js,.vue --ignore-path .gitignore --fix src",
    // 自动格式化当前项目受支持的文件
    "format": "prettier --write \"src/**/*.{js,vue,ts,json,css,scss}\""
  }
}

并行运行多个构建命令（npm-run-all） ​

json
{
  "scripts": {
    "dev": "vite",
    "dev-child:vue2": "cd vue2 && npm run dev",
    // 同时并行运行 dev 命令和所有以 dev-child 开头的命令
    "dev:all": "npm-run-all --parallel dev dev-child:*"
  },
  "devDependencies": {
    "npm-run-all": "^4.1.5"
  }
}

老旧项目运行报错：error:0308010C:digital envelope routines::unsupported ​

1. 错误原因分析 ​

Node.js 17+ 将底层的 OpenSSL 从 1.1.1 升级到了 OpenSSL 3.0，默认禁用了 MD4 等已被证实不安全的旧哈希算法。老版本的 Webpack 4、vue-cli-service 或其插件内部仍在调用这些旧哈希算法生成资源摘要，从而触发此报错。

2. 解决方案 ​

  • 方案一：跨平台兼容配置（推荐的临时绕过方案） 直接使用 Windows SET 命令在 Linux / macOS / CI 环境会直接报错，推荐借助 cross-env 实现跨平台：

    bash
    npm install -D cross-env

    在 package.json 中配置：

    json
    {
  "scripts": {
    "dev": "cross-env NODE_OPTIONS=--openssl-legacy-provider vite",
    "build": "cross-env NODE_OPTIONS=--openssl-legacy-provider vue-cli-service build"
  }
}

  • 方案二：彻底解决（现代化推荐）

    • 将 Webpack 升级到 5.54+（内部已重构哈希生成算法，支持 Node 17+ 且无需 Legacy 参数）。
    • 将老旧构建脚手架逐步迁移至 Vite 或 Rsbuild。
