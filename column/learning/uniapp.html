微信开发者工具运行小程序项目后登录报错：不在合法域名内 ​

原因：微信小程序开发环境中未开启域名校验忽略。 解决方法：点击微信开发者工具右上角“详情” -> “本地设置” -> 勾选“不校验合法域名、web-view（业务域名）、TLS版本以及HTTPS证书”。

UniApp 项目导入 UI 组件库（uView / uview-plus） ​

NOTE

  • Vue 2 项目：使用 uview-ui（1.x 或 2.x）。
  • Vue 3 项目：官方推荐使用 uview-plus 或现代组件库 wot-design-uni，直接引入 uview-ui 会因为 Vue 2 Options API 语法及底层 API 差异报错。

Vue 2 项目以插件方式导入 uView： ​

  1. 打开 DCloud 插件市场，搜索 uview-ui，选择“下载插件并导入 HBuilderX”。
  2. main.js 中引入并挂载：
js
import uView from "@/uni_modules/uview-ui";
Vue.use(uView);
  1. uni.scss 中导入主题样式：
scss
@import "@/uni_modules/uview-ui/theme.scss";
  1. 在 App.vue 以及各组件的 <style> 标签上添加 lang="scss"：
vue
<style lang="scss"></style>

java 环境变量配置(uniapp 本地打包 apk 生成证书签名的时候会用到) ​

JAVA_HOME 为 jdk 的实际安装路径，Path 和 CLASSPATH 的路径通用,直接复制即可

  1. JAVA_HOME：D:\Program Files\Java\jdk-1.8
  2. Path：①%JAVA_HOME%\jre\bin ②%JAVA_HOME%\bin
  3. CLASSPATH：.;%JAVA_HOME%\lib\dt.jar;%JAVA_HOME%\lib\tools.jar;

不同机型的 CPU 类型不同,需要在 manifest.json 文件中切换 APP 常用其他设置,勾选支持 CPU 类型:armeabi-v7a 和 arm64-v8a

uniapp 中使用 iData 条码扫描插件实现 PDA 扫描头扫描功能(将插件作为本地插件来使用) ​

  • 打开 uniapp 插件市场，搜索 iData 条码扫描插件，下载 for 离线打包，将插件解压放在 nativeplugins 文件夹下，再将文件夹放入 uniapp 项目的根目录里
  • 打开 manifest.json 文件，切换到 App 原生插件配置选项，找到本地插件，点击选择本地插件，导入刚刚的插件即可
  • 在需要使用插件的页面的 script 标签里引入
vue
<script>
  const barcodeModel = uni.requireNativePlugin("iData-BarcodePlugin-BarcodeModule")
  const modal = uni.requireNativePlugin('modal');
  const globalEvent = uni.requireNativePlugin('globalEvent');
  export default {}
</script>
  • 在页面加载的时候初始化插件并添加全局监听事件
js
 onLoad() {
   // #ifdef APP-PLUS
    this.initPad();
    let that = this;
    globalEvent.addEventListener("iDataBarcodeEvent", that.pdaWatch);
    // #endif
  }
  methods: {
    // 初始化扫描
    initPad() {
    barcodeModel.initScan((ret) => {
      console.log('初始化扫描' + JSON.stringify(ret))
    });
   },
    // 扫描处理事件
    pdaWatch(e) {
    console.log(JSON.stringify(e));
        const url = e?.barcode
   }
  }
  • 在页面卸载的时候关闭扫描头并全局移除事件
js
 onUnload() {
   // #ifdef APP-PLUS
    let that = this;
    barcodeModel.closeScan((ret) => {
      console.log(ret);
    });
    globalEvent.removeEventListener("iDataBarcodeEvent", that.pdaWatch)
    // #endif
  },
  • 在需要打开扫描头的地方绑定点击事件
js
 clickPda() {
    barcodeModel.scanStart((ret) => {
      console.log('开始扫描' + JSON.stringify(ret))
    }
  }

电脑给安卓手机或者 pda 安装 apk 安装包的方法 ​

方法一:使用 360 手机助手安装或者微信,qq 来实现安装 方法二:使用 adb 来安装：

  1. 下载 adb：https://dl.google.com/android/repository/platform-tools-latest-windows.zip：解压到任意目录， 例如放在 D:\Program> Files 文件夹下面， 这样 adb 的目录就是 D:\Program Files\platform-tools
  2. 配置 adb 环境变量：此电脑->系统属性->高级系统设置->环境变量->系统变量->path->新建->输入 adb 目录。终端输入 adb --version,验证是否成功
  3. 使用命令进行安装 apk 文件:adb install D:\APKlxb\simpleDemo-release.apk 注意：如果电脑中已有 Android Studio,则不需要下载 adb,只需要配置环境变量即可 环境变量也可以这样配置： adb_home:C:\Users\user\AppData\Local\Android\Sdk\platform-tools path:%adb_home%

uToast 同时只会存在一个,代码中如果同时写了多次触发条件,后面触发的弹窗的会覆盖前面的,前面的弹窗不再触发。以下代码只会触发第二个弹窗。

js
const fun = () => {
  this.$refs.uToast.show({
    title: "请扫描正确的二维码",
    type: "error",
  });
  this.$refs.uToast.show({
    title: "请扫描正确的二维码2",
    type: "error",
  });
};

该 modal 附带 return 功能，一旦触发会终止函数,阻止后续代码运行。以下代码中打印语句不再执行。

js
const fun = () => {
  modal.toast({
    message: "收到条码：" + JSON.stringify(e),
    duration: 1.5,
  });

};

uniapp 打包 apk,安装后提示打包时未添加 oauth 模块 ​

解决方法是找到 manifest.json,切换到 APP 权限配置,勾选 OAuth 登录鉴权(不要勾选子选项),重新打包即可

uniapp 打包 apk,安装后提示:不匹配的版本可能造成应用异常 ​

如本应用使用 HBuilderX 3.1.12 或对应的 cli 版本编译，而手机端 SDK 版本是 3.1.13，不匹配的版本可能造成应用异常

解决方法是在 manifest.json 文件的源码视图中配置忽略这个提醒

js
"app-plus": {
    "compatible": {
        "ignoreVersion": true //true表示忽略版本检查提示框，HBuilderX1.9.0及以上版本支持
    },
},

uniapp 打包自定义基座到安卓设备 ​

  1. 数据线连接电脑和安卓设备,打开安卓设备的 USB 调试功能,USB 功能仅充电改为传输文件
  2. 打开 hbuilderx,点击运行到手机或模拟器,点击制作自定义调试基座,进入到打包页面
  3. 在打包页面勾选使用云端证书,打自定义调试基座和传统打包,点击打包即可
  4. 打包完成后,再次点击运行到手机或模拟器,点击运行到 Android App 基座
  5. 运行完成之后会在安卓设备上提示是否允许安装(第一次会提示),同意即可完成安装 注意: 基座包和正式包不能同时存在同一个设备上,每次更改完代码如果不报错会自动更新基座包(安卓设备表现为自动退出软件再重新进入),如果报错提示运行已停止,则需要删除基座包重新运行

uniapp 打包自定义基座时提示自定义基座版本和上次版本相同，将会导致运行到手机时不会自动更新基座 ​

修改版本号方法：打开 manifest.json 文件,在基础配置中修改应用版本名称和应用版本号即可

uniapp 项目运行到微信小程序 v-show 不生效 ​

h5 端正常,小程序端不生效可能是 v-show 放在了自定义组件上，需要使用 view 标签包裹组件, 将 v-show 指令放到 view 标签上(不可以使用 text 标签包裹,会使组件不显示)

js
// 正确写法
<view v-show="!play">
  <u-icon size="40" name="pause-circle-fill"></u-icon>
</view>
<view v-show="play">
  <u-icon size="40" name="play-circle-fill"></u-icon>
</view>
// 错误写法1
<u-icon v-show="!play" size="40" name="pause-circle-fill"></u-icon>
<u-icon v-show="play" size="40" name="play-circle-fill"></u-icon>
// 错误写法2
<text v-show="!play">
  <u-icon size="40" name="pause-circle-fill"></u-icon>
</text>
<text v-show="play">
  <u-icon size="40" name="play-circle-fill"></u-icon>
</text>

uniapp 中使用媒体方法 uni.createInnerAudioContext()时运行到小程序端异常 ​

h5 端正常,微信小程序端无法获取 audio 文件的时长 duration。因为小程序端不支持 onCanplay 里面获取 duration, 需要在 onTimeUpdate 里面获取 duration

js
// h5端
innerAudioContext.onCanplay(() => {
  max.value = duration.value = Math.floor(innerAudioContext.duration);
  if (max.value) {
    if (!sliderSetIntervalFlag) {
      sliderSetInterval();
    }
  }
});
// 小程序端
innerAudioContext.onTimeUpdate(() => {
  if (!max.value) {
    max.value = duration.value = Math.floor(innerAudioContext.duration);
    sliderSetInterval();
  }
});

uniapp 中跳转外部链接适配多端的写法 ​

通过条件编译实现对 h5,小程序以及 app 端的不同处理,item.mobilUrl 为实际地址路径

js
// 跳转外部链接
const clickItem = (item: Data) => {
  // #ifdef APP-PLUS
  if (typeof plus !== "undefined") {
    plus.runtime.openURL(item.mobilUrl); //这里默认使用外部浏览器打开而不是内部web-view组件打开
  }
  // #endif
  // #ifdef H5
  window.open(item.mobilUrl);
  // #endif
  // #ifdef MP
  if (inWhiteList.value) {
    //如果在小程序的网址白名单中，会走内置webview打开，否则会复制网址提示在外部浏览器打开
    uni.navigateTo({
      url: "/pages/component/web-view/web-view?url=" + item.mobilUrl,
    });
  } else {
    uni.setClipboardData({
      data: item.mobilUrl,
    });
    uni.showModal({
      content:
        "本网址无法直接在小程序内打开。已自动复制网址，请在手机浏览器里粘贴该网址",
      showCancel: false,
    });
  }
  // #endif
};

从hbuilderx点发布到微信小程序失败，您不是这个应用的项目成员: ​

或者你可以双击打开 manifest.json 的可视化视图 -> 选择「基础配置」 -> 点击 AppID 旁边的「重新获取」按钮，它会自动为你当前的 DCloud 账号生成一个新的 ID。 第二步：重新运行「发行」 修改并保存 manifest.json 后，在 HBuilderX 顶部菜单栏重新点击 「发行」 -> 「小程序 - 微信」。 这次 HBuilderX 会一路绿灯编译成功，并在编译时剔除 vendor.js 中的调试信息并进行混淆压缩（体积会从 2.29MB 瞬间缩减到 300KB 左右）。 第三步：在微信工具中导入 build 包 编译成功后，打开微信开发者工具。 重新导入项目，将路径指向发行后的包：unpackage/dist/build/mp-weixin。 此时查看依赖分析，你的主包体积应该在 600KB - 900KB 左右，远低于 2MB 限制，不管是真机调试还是直接点击右上角「上传」发布，都不会再有任何体积报错！

uniapp 项目中原生 tabBar 图标偏大、粗糙或高低不齐的调整方案 ​

现象: 在 pages.json 中配置原生 tabBar 后，图标在真机或微信开发者工具中看起来非常粗大、拥挤且高低不齐。

原因: 微信小程序的原生 TabBar 渲染机制是将 PNG 切图统一放进固定的 27px × 27px 展示框中。若 PNG 切图素材的主体图形满版占满画布（缺少透明留白 Padding），渲染时就会撑满 27px 的容器，显得极为粗大。

解决方法: 使用“固定标准画布 + 透明留白”的方式重新处理图标素材：

  1. 画布尺寸：统一设置为 81px × 81px 透明背景 PNG（微信小程序 @3x Retina 标准）。
  2. 图形缩放与居中：将实际图标主体图形等比例缩小至 50px ~ 54px 左右，居中放置在 81px 画布正中间（四周留出约 14px 透明边距）。

通过透明留白 Padding，原生容器在渲染 27px 框时，主体图形的视觉展示尺寸会自然缩小到更精细的 ~17px，且各个 Tab 保持高度绝对一致。

可使用 Node.js 脚本（基于 Jimp 库）批量处理 static/tabbar 目录下的所有图标：

js
const Jimp = require('jimp');
const fs = require('fs');
const path = require('path');

const targetDir = path.join(__dirname, '../src/static/tabbar');
const files = fs.readdirSync(targetDir).filter(f => f.endsWith('.png'));

async function resizeTabBarIcons() {
  const CANVAS_SIZE = 81; // 微信小程序标准 @3x 画布尺寸
  const ICON_SIZE = 52;   // 主体图形目标视觉尺寸
  const OFFSET = Math.floor((CANVAS_SIZE - ICON_SIZE) / 2); // 居中偏移 14px

  for (const file of files) {
    const imgPath = path.join(targetDir, file);
    const srcImg = await Jimp.read(imgPath);
    const canvas = new Jimp(CANVAS_SIZE, CANVAS_SIZE, 0x00000000);

    srcImg.contain(ICON_SIZE, ICON_SIZE);
    canvas.composite(srcImg, OFFSET, OFFSET);
    await canvas.writeAsync(imgPath);
  }
}

resizeTabBarIcons();

微信小程序发布新版本后残留旧版本样式/代码缓存（必须删除小程序才能更新）的根治方案 ​

1. 现象与痛点 ​

小程序在微信公众平台发布新的正式版后，老用户手机中依然运行上一版本的旧界面或旧样式，即使退出重新进入小程序也没用，必须在微信“最近使用”列表里长按彻底删除小程序再重新扫码/搜索添加，才能拉取到最新版本。

2. 根本原因剖析 ​

这是由微信小程序的“异步冷启动更新”机制决定的：

  • 优先秒开旧包：为了保证秒开体验，用户冷启动时微信会优先直接加载本地磁盘中已缓存的旧代码包（旧 WXSS、旧 JS、旧 WXML）。
  • 后台静默下载，缺少重启指令：微信虽会在后台异步下载新版本代码包，但如果小程序代码内没有接入 wx.getUpdateManager() 监听并在下载完成后调用 applyUpdate()，微信即便下好了新包也不会自动替换当前运行的进程；甚至多次进出小程序（热启动）也依然在运行本地旧包，造成长期缓存滞后。

3. 完整改造方案与实施记录 ​

本次治理包含两阶段改动（Codex 基础机制构建 + 后续强制更新与开发环境净化）：

第一阶段：Codex 实施的底层更新与缓存管理机制 ​

  1. 接入微信原生 getUpdateManager 控制器：
    • 封装 src/utils/app-update.ts，在 App.vue 的 onLaunch 与 onShow 中初始化并监听版本更新状态。
    • 监听 manager.onUpdateReady（新版本在后台 100% 下载完毕）回调。
  2. 防打扰白名单与主页面补查：
    • 设置 UPDATE_PROMPT_ROUTES 白名单，弹窗限制在 5 大 TabBar 页面（首页、分类、拼团、购物车、我的）触发，杜绝在用户提交订单、输入地址或发起支付等关键链路中突然弹窗打断。
    • 各 Tab 页面配置 onPageShow 补查机制：用户即使从分享海报直接进入二级详情页，返回主大厅后仍会自动补弹更新提示。
  3. 正式版缓存版本迁移 (migrateReleaseCache)：
    • 在版本号变化时（miniProgram.version 更新），自动清理容易引发数据陈旧的可重建业务缓存（如本地快照等），但严格保留登录 Token、购物车与地址选择数据。

第二阶段：后续优化（强制更新与开发环境去冗） ​

  1. 去掉“稍后再说”，升级为“强制更新”：
    • 痛点：初始版本弹窗提供了“立即更新”与“稍后再说”。如果老用户顺手点击“稍后再说”，在本次使用中依然会驻留在老样式中，无法彻底根除老样式残留。
    • 改动：将弹窗配置改为 showCancel: false，主按钮设为“立即重启”。
    • 体验优势：当 onUpdateReady 触发时，新代码包已经在后台下载到手机本地。点击“立即重启”仅需 0.3 秒瞬间载入新包，无需用户等待下载、零流量消耗，体验平滑且彻底消灭老样式与旧接口兼容问题。
  2. 清理开发环境预览残留（移除 previewUpdate=1 与构建宏）：
    • 痛点：前期为了预览弹窗效果注入了构建宏 __APP_UPDATE_PREVIEW_ENABLED__ 与定时器 updatePreviewTimer，导致本地开发切换窗口或传参时频繁反复弹窗。
    • 改动：彻底清理开发预览冗余代码与构建常量，让代码与生命周期恢复轻量纯粹；真正的更新流程直接依托微信开发者工具官方的【工具 -> 模拟更新】进行无侵入测试。

4. 核心实现代码 ​

(1) 版本更新控制器 (src/utils/app-update.ts) ​

ts
const CACHE_VERSION_KEY = 'mall_app_cache_version'
const CACHE_SCHEMA_VERSION = 1

// 仅清理可重建的服务端数据快照，不清空用户登录态、购物车或地址
const REBUILDABLE_CACHE_KEYS = [
  'MALL_APP_FEATURE_MAP_CACHE',
  'local_created_orders',
  'current_supplier_goods_detail'
]

// 限制仅在主大厅页面弹窗，避免打断下单、支付与表单输入
const UPDATE_PROMPT_ROUTES = new Set([
  'pages/index/index',
  'pages/category/category',
  'pages/group-buy/group-buy',
  'pages/cart/cart',
  'pages/mine/mine'
])

// 强更配置：隐藏取消按钮，点击后瞬间重启应用
const updatePromptOptions = (confirm: () => void): UniApp.ShowModalOptions => ({
  title: '版本更新',
  content: '新版本已准备好，重启后即可使用。',
  showCancel: false,
  confirmText: '立即重启',
  success: (result) => {
    if (result.confirm) confirm()
  }
})

/** 正式版首次启动/版本变化时，仅迁移明确允许失效的缓存 */
export function migrateReleaseCache() {
  try {
    if (typeof uni.getAccountInfoSync !== 'function') return
    const { miniProgram } = uni.getAccountInfoSync()
    if (miniProgram.envVersion !== 'release' || !miniProgram.version) return
    const cacheVersion = `${miniProgram.version}:${CACHE_SCHEMA_VERSION}`
    if (uni.getStorageSync(CACHE_VERSION_KEY) === cacheVersion) return
    for (const key of REBUILDABLE_CACHE_KEYS) uni.removeStorageSync(key)
    uni.setStorageSync(CACHE_VERSION_KEY, cacheVersion)
  } catch (error) {
    console.warn('版本缓存迁移未完成:', error)
  }
}

export function createAppUpdateController() {
  let manager: UniApp.UpdateManager | undefined
  let ready = false
  let failed = false
  let visible = false
  let prompting = false
  let timer: ReturnType<typeof setTimeout> | undefined

  const prompt = () => {
    if (!visible || prompting || (!ready && !failed)) return
    const pages = getCurrentPages()
    const route = pages[pages.length - 1]?.route || ''
    if (!UPDATE_PROMPT_ROUTES.has(route)) return

    if (failed) {
      failed = false
      uni.showToast({ title: '新版本下载失败，请检查网络后重新打开', icon: 'none' })
      return
    }

    prompting = true
    uni.showModal({
      ...updatePromptOptions(() => {
        if (ready) manager?.applyUpdate() // 瞬间重启并应用新代码包
      }),
      complete: () => { prompting = false }
    })
  }

  const schedulePrompt = () => {
    if (timer !== undefined) clearTimeout(timer)
    timer = setTimeout(() => { timer = undefined; prompt() }, 300)
  }

  return {
    init() {
      if (manager || typeof uni.getUpdateManager !== 'function') return
      try {
        manager = uni.getUpdateManager()
        manager.onUpdateReady(() => { ready = true; failed = false; schedulePrompt() })
        manager.onUpdateFailed(() => { ready = false; failed = true; schedulePrompt() })
      } catch (error) {
        console.warn('版本更新管理器初始化失败:', error)
      }
    },
    onShow() {
      visible = true
      schedulePrompt()
    },
    onPageShow() { schedulePrompt() },
    onHide() {
      visible = false
      if (timer !== undefined) clearTimeout(timer)
      timer = undefined
    }
  }
}

export const appUpdateController = createAppUpdateController()

  1. 如何提前验证：不需要等正式发版盲测。在微信开发者工具顶部菜单点击【工具 -> 模拟更新】编译运行，即可 100% 模拟真实更新弹窗与 applyUpdate() 重启流程。

微信小程序单人/单微信号模拟“多用户裂变与邀请绑定”调试实战 ​

在开发电商或社区拼团小程序时，经常会遇到“邀请好友得券/返佣”、“拼团凑单”、“关系绑定”等强依赖多用户互动的业务场景。传统测试往往需要借多台手机、注册多个微信号，效率极低且账号状态容易受历史数据污染。利用微信开发者工具内置的原生能力，可以完全实现单人、单机、单微信号搞定完整的端到端裂变闭环测试。

1. 核心痛点与解决思路 ​

  • 痛点：当前微信号已是“老用户”或具备特殊身份（如分销员/团长），无法测试“纯普通新用户”被邀请绑定的首登奖励；身边又没有多余的微信进行端到端对测。
  • 思路：
    1. 开发者工具「多账号调试」：官方提供的独立多实例沙箱，可无限制生成全新虚拟用户，多窗口并排运行，互不干扰。
    2. 带参自定义编译：通过模拟器启动参数（如 inviteCode=xxxx）精准模拟微信好友卡片、朋友圈海报扫码进入的场景。
    3. 双测试新人对测法：抛开主账号的历史包袱，用两个虚拟测试号分别充当“邀请人”和“受邀新人”，环境最纯净。

2. 单机多账号并排调试全流程 ​

步骤一：创建【账号 A（测试邀请人）】 ​

  1. 打开微信开发者工具，在顶部菜单栏点击：「工具」->「多账号调试」。
  2. 在弹出窗口中点击 「添加测试号」，工具会自动唤起一个全新的、完全隔离的独立模拟器窗口。
  3. 在测试号 A 中登录小程序，此时账号 A 是 0 历史包袱的普通会员：
    • 进入「我的」-> 点击「邀请有礼」页面；
    • 查看/复制专属邀请码（例如 8158C155）。

步骤二：创建【账号 B（测试受邀新人）】 ​

  1. 在多账号调试管理窗口中，再次点击 「添加测试号」，生成第三个模拟器窗口（账号 B）。
  2. 配置模拟新人“点击邀请链接/扫码进入”：
    • 在账号 B 模拟器顶部，点击编译模式下拉框 -> 「添加编译模式」；
    • 模式名称：邀请进站-测试
    • 启动页面：pages/index/index（或具体的分享承接页）
    • 启动参数：inviteCode=8158C155（填入账号 A 的邀请码）
    • 点击确定并编译启动。
  3. 此时账号 B 模拟器会携带 inviteCode 参数冷启动，在账号 B 中完成首次登录/注册，系统将自动触发新人与 A 的关系绑定。

3. 邀请业务奖励闭环验证清单 ​

以经典的“普通会员邀请有礼（注册奖 + 首单奖）”体系为例，验证路径如下：

text
[测试号 A 产出邀请码] 
       │
       ▼
[测试号 B 带参启动并注册] ──(约30秒内)──> 【触发双方注册奖励】
       │                                     ├─ A端：邀请人数+1，到账邀请注册券
       │                                     └─ B端：卡券包到账受邀新人券
       ▼
[测试号 B 下首单并支付] 
       │
       ▼
[管理后台执行“核销/收货完成”] ───────────> 【触发邀请人首单完成奖】
                                             └─ A端：拉新券总数+1，到账首单完成奖励券
  1. 验证双方首次注册奖励：
    • 新人 B 端：打开「我的」->「我的优惠券」，检查是否实时（或30秒内）到账【受邀新人券】。
    • 邀请人 A 端：刷新「邀请有礼」，检查【邀请人数】是否累加为 1，优惠券明细是否记录【邀请新用户注册奖励】并到账。
  2. 验证新人首单完成奖励：
    • 用新人 B 在商城内下一笔自提/快递订单并完成支付。
    • 打开运营管理后台，找到该笔订单执行确认收货或自提驿站核销（订单状态变为 COMPLETED）。
    • 切换回邀请人 A 模拟器，刷新「邀请有礼」，检查【拉新优惠券】数量是否累加，并到账【新人首单完成奖励】。

4. 常见避坑指南 ​

  1. 主账号身份污染时的快速切换：
    • 若必须使用自己当前的真实微信测试普通用户形态，且当前账号已开通了分销员/团长：
    • 推荐做法：直接在管理后台的「分销管理」名册中找到自己，点击 「禁用」；小程序下拉刷新立即降级为普通会员视图。测试完毕后再点 「启用」 即可无损复原，无需清缓存或重新授权。
  2. 启动参数解析陷阱：
    • 小程序分享路径的参数（path: /pages/index/index?inviteCode=xxx）与太阳码 scene 参数解析逻辑不同；测试时需确保业务代码能同时兼容解析 options.inviteCode 与 decodeURIComponent(options.scene)。
  3. 缓存跨账号串号预防：
    • 多账号调试的各实例 Storage 是物理隔离的；但若在主模拟器上直接通过「清缓存」测试新账号，务必使用 「清除全部缓存」 或 「清除登录数据」，避免本地旧 Token 拦截了静默绑码请求。
