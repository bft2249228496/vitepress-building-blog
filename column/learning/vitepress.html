VitePress 部署方案：源码私有仓到公开构建仓 ​

在实际博客维护中，通常采用源码仓库与构建产物仓库分离的模式：

  • 源码私有仓：vitepress-blog（存放 Markdown 源文件与站点配置文件）
  • 构建公开仓：vitepress-building-blog（专门开启 GitHub Pages，存放静态构建产物）

方案一：GitHub Actions CI/CD 自动化部署（现代推荐） ​

无需在本地执行任何打包和推送脚本，本地只管提交源码并推送到 GitHub，由云端 Runner 自动完成编译并跨仓库同步发布。

1. 工作流文件 .github/workflows/deploy.yml ​

yaml
name: Deploy Docs to Building Repo

on:
  push:
    branches:
      - main
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Source Code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 10

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - name: Install Dependencies
        run: pnpm install --frozen-lockfile

      - name: Build Docs
        run: pnpm run docs:build

      - name: Deploy to vitepress-building-blog
        uses: peaceiris/actions-gh-pages@v4
        with:
          personal_token: ${{ secrets.ACCESS_TOKEN }}
          external_repository: bft2249228496/vitepress-building-blog
          publish_branch: gh-pages
          publish_dir: docs/.vitepress/dist
          commit_message: "deploy: ${{ github.sha }} [skip ci]"

2. 一次性权限配置步骤 ​

  1. 前往 GitHub 生成带 repo 权限的 Personal Access Token：Personal Access Tokens。
  2. 进入源码仓 vitepress-blog -> Settings -> Secrets and variables -> Actions。
  3. 新增 Repository secret，名称为 ACCESS_TOKEN，值为刚才复制的 Token。
  4. 后续只要在本地执行 git push origin main，GitHub Actions 就会自动打包部署至 vitepress-building-blog 的 gh-pages 分支。

方案二：本地自动化脚本部署（备用方案） ​

在本地项目根目录下创建 .deploy.sh 脚本：

sh
#!/usr/bin/env sh

# 遇到错误立即中断
set -e

# 1. 执行静态构建
pnpm run docs:build

# 2. 进入产物输出目录
cd docs/.vitepress/dist

# 3. 初始化临时 Git 仓库并提交
git init
git add -A
git commit -m 'deploy'

# 4. 强制推送到目标构建仓库的 gh-pages 分支
git push -f git@github.com:bft2249228496/vitepress-building-blog.git master:gh-pages

# 5. 返回根目录
cd -

在本地 Git Bash 终端中运行：

bash
chmod +x .deploy.sh
./.deploy.sh

博客评论系统方案对比与选型 ​

TIP

  • Giscus（强烈推荐）：基于 GitHub Discussions 社区讨论区，无需注册 OAuth App，不暴露任何私钥，无需反代服务器，官方提供 @giscus/vue 组件，多端适配与深色主题切换体验极佳。
  • Gitalk（传统方案）：基于 GitHub Issues，需要申请 OAuth 鉴权并在前端传递 clientSecret，且依赖海外第三方反向代理解决 CORS 问题，易受网络环境波动影响。

Giscus 现代接入方式（推荐） ​

  1. 在 GitHub 目标公开仓库中开启 Discussions 功能。
  2. 访问 giscus.app 生成配置参数（repoId、categoryId 等）。
  3. 安装依赖并在自定义 Layout 中挂载：
bash
pnpm add @giscus/vue
vue
<template>
  <Layout>
    <template #doc-footer-after>
      <Giscus
        repo="bft2249228496/vitepress-building-blog"
        repo-id="YOUR_REPO_ID"
        category="General"
        category-id="YOUR_CATEGORY_ID"
        mapping="pathname"
        strict="0"
        reactions-enabled="1"
        emit-metadata="0"
        input-position="top"
        :theme="isDark ? 'dark' : 'light'"
        lang="zh-CN"
        loading="lazy"
      />
    </template>
  </Layout>
</template>

<script setup>
import DefaultTheme from 'vitepress/theme'
import { useData } from 'vitepress'
import Giscus from '@giscus/vue'

const { Layout } = DefaultTheme
const { isDark } = useData()
</script>

将 VitePress 项目私有化部署到威联通 NAS ​

  1. 打包静态产物：在项目根目录运行 pnpm run docs:build。
  2. 开启 Web 服务：登录威联通 NAS 管理后台，打开“Web 服务器”，勾选启用服务。
  3. 上传网站文件：在 NAS 文件管理器中进入 web 根目录，新建子文件夹 vitepress-building-blog（需与 config.ts 中的 base 路径名称保持一致），将本地 docs/.vitepress/dist 下的全部静态资源上传至该文件夹。
  4. 外网访问与反代配置：通过 Lucky 穿透工具配置 IPv6 端口转发与反向代理，即可实现外网无缝访问 NAS 托管的私人博客站点。
