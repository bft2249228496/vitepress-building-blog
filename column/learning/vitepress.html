vitepress 部署到 github 任意仓库详细步骤 ​

1.将 vitepress 项目发布到 github 的公开仓库，设定该项目命名为 vitepress-blog 2.从 vscode 中创建新分支 gh-pages,发布该分支到 github 上 3.切回 main 分支,在项目根目录下创建脚本文件.deploy.sh,内容如下:

sh
#!/usr/bin/env sh

# 确保脚本抛出遇到的错误
set -e

# 构建
pnpm run docs:build

# 进入生成的构建文件夹
cd docs/.vitepress/dist

# 如果是发布到自定义域名
# echo 'www.example.com' > CNAME

# 此处作用是在本地dist目录下初始化一个新的git仓库,进行添加和提交操作,此仓库默认分支为master
git init
git add -A
git commit -m 'deploy'

# 如果发布到 https://<USERNAME>.github.io/<REPO>
# 此处作用为将dist目录master分支下的文件合并到远程源码仓库即vitepress-blog的gh-pages分支下
git push -f git@github.com:bft2249228496/vitepress-blog.git master:gh-pages
# (我的个人building仓库为vitepress-building-blog.git，推送命令为git push -f https://github.com/bft2249228496/vitepress-building-blog.git master:gh-pages,或者git push -f git@github.com:bft2249228496/vitepress-building-blog.git master:gh-pages)
# 如果本地打包分支默认为main,则推送命令为git push -f https://github.com/bft2249228496/vitepress-blog.git main:gh-pages,或者git push -f git@github.com:bft2249228496/vitepress-blog.git main:gh-pages
# 回到原目录
cd -

4.在 github 上的 vitepress-blog 仓库中进行操作:点击 setting，点击 pages，找到 Branch 项,修改分支为 gh-pages,根目录为/(root)，点击 save 5.修改.vitepress/config.ts,添加 base 属性和值

js
export default defineConfig({
  base: '/vitepress-blog/',
})

6.打开 git bash,执行命令:

sh
# 将.deploy.sh 文件设置为可执行文件
chmod +x .deploy.sh
# 运行脚本文件.deploy.sh
./.deploy.sh

7.可选操作: 在 vscode 中新建一个 building 文件仓库,如 vitepress-building-blog,发布到 github 上,新建 gh-pages 分支,再发布到 github 上,将原来的 vitepress-blog 仓库设置成私密仓库，对新的 vitepress-building-blog 仓库进行第 4 步操作，修改.deploy.sh 文件

sh
#!/usr/bin/env sh

# 确保脚本抛出遇到的错误
set -e

# 构建
pnpm run docs:build

# 进入生成的构建文件夹
cd docs/.vitepress/dist

# 如果是发布到自定义域名
# echo 'www.example.com' > CNAME

git init
git add -A
git commit -m 'deploy'

# 如果发布到 https://<USERNAME>.github.io/<REPO>
git push -f git@github.com:bft2249228496/vitepress-building-blog.git master:gh-pages

cd -

修改.vitepress/config.ts,修改 base 的值,然后执行第 6 步操作

js
export default defineConfig({
  base: '/vitepress-building-blog/',
})

vitepress 接入 gitalk 评论系统的详细步骤 ​

  1. 因为官方的 gitalk 不再维护,fork 社区大佬修改版本的 gitalk 仓库
  2. 在 github 中点击 settings,点击 Developer settings,点击 OAuth Apps,点击 new OAuth application,填写如下内容，点击生成得到 Client ID 和 Client secrets 的值,复制保存起来
    Application name*Homepage URL*Application descriptionAuthorization callback URL*Enable Device Flow
    应用名(有意义即可)博客部署地址应用描述回调地址(和博客部署地址相同即可)推荐勾选
  3. 修改 package.json 文件,添加以下内容后,控制台执行 npm install
js
 "devDependencies": {
    "gitalk": "https://github.com/bft2249228496/gitalk.git", //此处为fork后的自己仓库地址
  },

4.新建.vitepress/theme/index.ts 文件,写入以下内容

js
import DefaultTheme from 'vitepress/theme'
import './custom.css'
import MyLayout from './MyLayout.vue'

export default {
  ...DefaultTheme,
  Layout: MyLayout,
}

5.新建.vitepress/theme/MyLayout.vue 文件，写入以下内容

vue
<template>
  <Layout />
</template>

<script setup>
import DefaultTheme from 'vitepress/theme'
import { watch, nextTick, onMounted } from 'vue'
import 'gitalk/dist/gitalk.css'
import Gitalk from 'gitalk'
import { useRouter } from 'vitepress'

const { Layout } = DefaultTheme

let { route } = useRouter() // 页面路由对象

onMounted(() => {
  watch(
    () => route.path, // 监听路由变化，重新挂载评论组件
    () => {
      nextTick(() => {
        if (typeof window !== undefined) {
          const content_div = document.querySelector('.content-container') // 查找页面内容DOM节点，此节点只有layout为Page（默认layout属性）的md文档才有
          if (content_div) {
            const before_s_div = document.getElementById('gitalk-page-container') // 获取页面评论组件DOM节点
            if (before_s_div) {
              // 判断是否已有评论组件节点，有则删除，重新创建。
              content_div.removeChild(before_s_div)
            }
            const s_div = document.createElement('div') // 创建节点
            s_div.setAttribute('id', 'gitalk-page-container') // 设置id
            content_div.appendChild(s_div) // querySelector的节点可自己根据自己想加载的地方设置
            const gitment = new Gitalk({
              id: { name: `${location.pathname.replace(/\W/g, '')}` }, // 可选，推荐设置为页面标题，因为会作为标签传给Github issues，且issues标签有长度限制。
              owner: 'bft2249228496', // GitHub repository 所有者
              repo: 'vitepress-building-blog', // GitHub repository
              clientID: '0258d848cc7125ec42ba', // 自己的clientID
              clientSecret: '235f3c4d6e1953a0cf64d9d9280060afcf5a9356', // 自己的clientSecret
              admin: ['bft2249228496'], // GitHub repository 所有者
              labels: [{ name: 'Gitalk' }], // GitHub issue 的标签
              createIssueManually: true, //如果当前页面没有相应的 isssue 且登录的用户属于 admin，则会自动创建 issue。如果设置为 true，则显示一个初始化页面，创建 issue 需要点击 init 按钮。
              proxy: 'https://vercel.younglina.top/github_access_token',
            })
            gitment.render('gitalk-page-container')
          }
        }
      })
    },
    { immediate: true }
  )
})
</script>

将 vitepress 项目部署到威联通 nas 上面 ​

  1. 对 vitepress 项目进行打包,在项目根目录执行以下命令
sh
pnpm run docs:build
  1. 登录威联通 nas,打开控制台,找到 web 服务器,勾选上启用 web 服务器,点击应用
  2. 在威联通中, 打开文件管理器，找到根目录下面的 web 文件夹, 新建一个文件夹, 命名为 vitepress-building-blog(此处命名应该与项目的.vitepress.config.ts 文件中 base 配置一致)
  3. 将 dist 文件夹(不包括文件夹本身)里面的所有文件都上传到新建的文件夹 vitepress-building-blog 中
  4. 再通过 lucky 配置 ipv6 的反向代理(lucky 反向代理的路径只能到端口号, 不能包含文件夹部分,需要手动拼接路径, 例如: /vitepress-building-blog)
  5. 访问 http://ipv6.lucky.com/vitepress-building-blog
